# SE-3 — the dashboard, rendered

Generated by `run_grafana_drill.py` against **Grafana 11.3.1** running in
WSL, provisioned with a Prometheus datasource and `ops/dashboard.json`.

`README.md` listed this under *What is NOT built*: the dashboard was
*asserted against the real exporter by tests and has never been
rendered by the thing that would render it*.

## Why a test was not enough

A test can check that every PromQL expression names a metric the
exporter emits. It cannot tell you whether Grafana accepts the file,
whether the panels bind to a datasource, or whether an expression that
parses returns anything. Three separate ways to be broken while every
test passes:

| failure | what an operator sees | why a test misses it |
|---|---|---|
| the file is rejected | the dashboard does not exist | the test reads the JSON itself, not Grafana's opinion of it |
| the panel is unbound | every panel says *No data* | the uid in the file need not match the provisioned one |
| the expression returns empty | a flat line, which reads as *nothing is happening* | the metric exists; no series matches the query |

The third is the dangerous one. **A dashboard that is silently empty
is worse than no dashboard**, because it is consulted during an
incident and answers *fine*.

### The series with no points

- **2. Approval rate vs the same time yesterday** — `sum(rate(gateway_decisions_total{decision="approve"}[15m] offset 1d)) / sum(rate(gateway_decisions_total[15m] offset 1d))`

Counted separately because a series with zero points is **not a
success**: it is precisely the flat line an operator misreads as
*nothing is happening*.

Here it is correct, and the reason is worth stating rather
than waving away. The empty one is the `offset 1d`
year-over-year comparison, and this Prometheus was started
minutes ago — **there is no yesterday to compare against.**
The panel is right and the drill is young.

Which is itself the finding: a comparison-against-yesterday
panel is blank for the first day of any deployment, and blank
in a way that looks like a broken query rather than like a
young database. Anyone standing this dashboard up for the
first time will see it and wonder.

## What this still is not

- **No image was rendered.** Grafana's PNG rendering needs the
  image-renderer plugin and a headless browser. This proves the panels
  resolve and return series; it does not prove they are legible, that
  the axes are sensible, or that the layout is not nonsense.
- **One Grafana, provisioned from a file.** No alerting rules in
  Grafana itself, no folder permissions, no users. The alert path lives
  in Prometheus and Alertmanager and is drilled by
  `run_prometheus_drill.py`.
- **The datasource uid is pinned by the provisioning script**, not by
  the committed JSON. That is the right way round for a repo that does
  not know the deployment's uid, and it means the *panel is unbound*
  failure is ruled out here by construction rather than tested.
